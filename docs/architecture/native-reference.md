# Native direction and behavioral reference

The owner selected a Rust host with upstream GPUI. Build GeppUI as an independently consumable GPUI component library. GeppIO composes product screens from it. NSH, GPUI Kit and Tauri are outside the selected foundation. Windows comes first, followed by Linux and then macOS. Web remains exploratory. Keep the Electron implementation runnable for comparison. [Preparation and exact reference revisions](https://github.com/rabrunos/GeppIO/issues/71)

The [native workspace](../../native/README.md) implements this direction: GPUI pinned at Zed v1.30.2, crate directions checked by `tools/check-modules.ts`, the main screen, then the widget engine, edit mode and catalog ([Stage B](https://github.com/rabrunos/GeppIO/issues/74)). `geppio-core` ports the TypeScript workbench model and is held to it by differential fixtures. Intentional differences approved in [Stage A](https://github.com/rabrunos/GeppIO/issues/73): tint-only peek backdrop, a peek that always animates and native Snap Layouts on Maximize. During Stage B the owner delegated implementation choices: a native choice may differ from Electron where Rust or GPUI justifies it, and each such difference is recorded in the Stage B Issue.

Choose native organization, algorithms, test harnesses and crate boundaries around Rust. Pin the selected upstream GPUI revision, review licensing and advisories, and test upgrades separately against the public library consumer, visuals and interactions. Each migration should identify its reference commit, input data, observable outcomes and any intentional difference requiring a decision.

| Behavior | Comparison scenarios |
| --- | --- |
| Shell and placement | Keep header, rail and status bar independent of the canvas. Resize Main on both axes, Sidebar at region width with vertical scroll, Bottom at region height without scroll. Exercise all eight anchors, clearance, local compression, reversal, cancellation and a constrained viewport. [Layout](layout.md) |
| Transactions and presentation | Compare individual edit gestures and normal paired resize, Save/Conclude/Cancel, whole-intention undo/redo and viewport-only projection. Restore exact bars, reservations and compositions after transfer, swap, archive or import. Test peek, collapse travel, interrupted animation, docking, overlays, maximize and tab continuity where supported. [Workbench scope](https://github.com/rabrunos/GeppIO/issues/2) |
| Visual and input fidelity | Compare both themes, localized text, clipping, focus return, keyboard navigation, reduced motion and 100%/125% scale on disposable Windows profiles. Physical DPI, pointer and IME checks retain their own acceptance. [Verification journeys](../development/testing.md) |
| Editor and files | Keep a basic editor independently usable without Explorer, Git, Terminal or project policy. Multiple views share text and history with independent selections and scroll. In full GeppIO, Explorer and editing are essential. Verify exact UTF-8/BOM/EOL bytes, multiple dirty documents, cancel/conflict/uncertain outcomes, close and recovery. [Documents](documents.md) · [Editor](monaco.md) |
| Workspace and tools | Reauthorize the root, revalidate selections, preserve shared terminal session/output bounds, exact Git grants, search cancellation and reviewed replacements. Compare direct open, detach and restore of supported shared views. Tools discovery reads passive metadata and effects need explicit actions. [Workspace](workspace.md) · [Tools](workspace-tools.md) · [Shared views](https://github.com/rabrunos/GeppIO/issues/64) |
| Plugin authors and users | Distinguish install identity, accepted generation, active model and visible view. Closing a view preserves active background work. Exercise external-folder editing, explicit refresh, rejected candidates and revocation. Prove custom UI beyond a predetermined widget set and measure warm edit-to-usable time against the desired ten-second target. [Plugins](plugins.md) |
| Communication, signing and storage | Bind calls and nested contributions to their real publisher. Exercise denied endpoints, stale grants and cancellation. Signed .gpp packages authenticate publisher and bytes; copies retain valid signatures, modified bytes require new signing. Verify installation-bound data retention and recovery. [Surfaces](plugin-surfaces.md) · [Packages](plugin-package.md) · [Data](plugin-data.md) |
| Independent products | Run an external GeppUI consumer and a basic editor consumer. Generate a selected Standalone app with its own product/data identity. Verify selected capabilities, disposal and absence of unrelated credentials and grants. [Standalone](../../src/geppio-standalone/README.md) |

The native plugin runtime, ABI, languages, sandbox, editor and terminal engines remain open. Test dynamic authoring, arbitrary presentation, background activity and isolated cross-plugin communication early. Re-establish filesystem, process, identity, resource and revocation boundaries on the native platform. Current Electron isolation evidence covers its own execution contexts only. Future external adoptions require individual owner review.
